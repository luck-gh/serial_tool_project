# 远程命令、BIN 下载与 CLI 窗口桥接

本文描述当前源码契约；版本及未发布改动见 [版本记录](VERSION_HISTORY.md)。旧 EXE 不会随源码自动更新，两端须使用支持下述能力的对应构建；构建由用户手动执行。

设备端连接硬件并提供 TCP 服务端监听;控制端作为 TCP 客户端连接设备端,远程发送指令并查看数据。运行状态的 `server/client` 分别对应设备端/控制端,协议标识不随界面文案改变。

## 命令支持盘点

GUI 按钮、发送编辑区、命令表和 SendMode 均进入主窗口/特殊命令管理器。远程设备操作进入带 ID 的 `device_request`，设备端实际执行后返回 `device_result`；上传下载使用独立 `firmware` 消息。CLI `--via-gui` 通过本机 IPC 进入同一个窗口后端。

| 入口/命令 | 本地 GUI | 控制端 GUI | 执行位置与完成含义 |
| --- | --- | --- | --- |
| 普通文本、SendHex | 支持 | 支持，已补齐结果回传 | 控制端编码，设备端串口写入；写入成功不等于设备命令执行成功 |
| 开串口/关串口按钮 | 支持 | 支持，已补齐实际结果和占用检查 | 设备端等待打开结果/线程停止；拒绝并行下载冲突 |
| 刷新端口 | 支持 | 支持 | 设备端枚举自己的端口后回传 |
| BaudRate | 支持 | 支持，已补齐校验、回执 | 在设备端设置；后续命令等待回执 |
| ComPort | 支持 | 已补齐 | 更新设备端串口选择；已打开句柄不切换，关闭重开后生效 |
| SetEndlog | 支持 | 支持 | 控制端本地设置发送结束符，无须远程设备操作 |
| delay | 支持 | 支持 | 控制端调度等待，不发送网络指令 |
| mode/modeend | 模块标记 | 模块标记 | 控制端解析；不是可执行的设备操作 |
| SendMode | 支持 | 支持 | 控制端解释模块，设备步骤经设备端执行；失败/超时停止后续步骤 |
| StopContinuous | 支持 | 支持 | 停止控制端流程；不能撤回已写入设备的数据 |
| 固件下载按钮、FirmwareDownload | 支持 | 已补齐上传和设备端下载 | 两入口共用模式、工具启用、文件和占用检查；等待下载终态 |
| 通用上传/下载、复位、读写寄存器 RPC | 无专用实现 | 无专用实现 | 不因存在原始串口发送就声称具备这些设备协议；须提供硬件协议才能新增 |

独立一次性 CLI 不支持 FirmwareDownload；常驻控制台的本机/GUI 后端支持下载，但独立后端只操作本机串口。网络远程仍需控制端和设备端 GUI，先通过一次性桥接完成连接，再进入控制台；操作流程及命令范围见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md#agent-远程操作流程)。

## 方案及参考

控制端上传 BIN，设备端调用现有 FirmwareDownloader。设备端已有完整串口参数和下载协议配置，开始命令、分包、CRC、ACK 与结束命令直接复用，网络延迟不进入逐字节 ACK 读取。不提供断点续传、通用 RPC 或自动包重发。

参考 [pySerial API](https://pyserial.readthedocs.io/en/latest/pyserial_api.html) 的短读、写入计数与超时契约，以及 [Python Socket HOWTO](https://docs.python.org/3.12/howto/sockets.html) 的流式分帧说明。CLI 桥接复用已有 PyQt5 的 [QLocalServer](https://doc.qt.io/archives/qt-5.15/qlocalserver.html) / QLocalSocket 与 QLockFile；没有新增依赖。

## TCP 消息契约

沿用 TCP、UTF-8 换行 JSON、Base64。单条 JSON 最多 128 KiB，接收端保留半帧、拆分粘包；二进制事件分块。设备端只服务一个控制端。沿用现有口令认证，该通道不提供 TLS。连接拥有本机 session 标记，排队消息和 Qt 槽拒绝旧连接数据。

认证完成后设备端发送 `{"type":"capabilities","firmware_upload":1,"device_results":1,"serial_config":1}`。控制端没有相应能力时拒绝操作，要求更新两端；不降级成不带回执的设备操作。`serial_config` 表示支持完整串口参数配置请求。

设备请求：`{"type":"device_request","id":"32位小写十六进制UUID","action":"write","config":{"data":"Base64"}}`。

| action | config | 回执 |
| --- | --- | --- |
| write | data，解码后 1–65536 字节 | 完整串口写入是否成功，无硬件命令 ACK 语义 |
| baudrate | value，1–4000000 整数 | 设备端设置结果；合法范围不代表硬件支持 |
| comport | port，非空名称 | 选择结果，不热切换现有句柄 |
| configure | port/baudrate/databits/parity/stopbits | 校验并保存设备端五项串口配置，要求串口关闭；不自动打开，等待实际保存结果 |
| open | port/baudrate/databits/parity/stopbits | 实际打开结果 |
| close | 空对象 | 实际关闭结果 |
| refresh_ports | 空对象 | 端口配置事件及完成回执 |

返回 `type=device_result,id,success,message`；`serial_config` 同步连接、占用和参数状态，`serial_data` 只用于设备端接收数据转发。设备请求等待 10 秒，未收到回执视为未知，不重发；设备端每个普通设备请求帧只尝试一次，不保存已完成请求历史，没有累计请求次数上限。ID 仅关联在途请求与回执，不提供跨帧幂等保证；相同 ID 的新请求帧仍是新操作，调用方不得重发结果未知的请求。迟到或重复回执在在途关联移除后忽略，重新连接不会重放旧命令。固件上传/下载的独立任务生命周期与去重规则保持不变。

普通 `write` 在设备端 GUI 线程同步执行,`device_result` 先进入发送 FIFO,串口线程 RX 回到同一 GUI 线程后才转发 `serial_data`;控制端按同一 TCP 流的消息顺序派发,包括同次读取的多个帧. 因此本次写入引起的 RX 在成功写入回执之后转发,不意味着异步/旧 RX 带有设备命令归属. 远程替换校验从成功回执处的当前 RX offset 开始,沿用原响应超时,不把网络排队当设备响应等待,也不回放此前数据;失败/未知仍沿用停止且不重发的契约.

### 本机 CLI 配置与连接控制

`remote-connect/remote-listen/remote-stop` 通过本机 GUI 桥接调用现有网络线程；连接等待认证、能力与串口状态同步，监听等待 bind/listen 成功。十秒未就绪则失败并停止本次线程；CLI 先超时退出则清理它尚未完成的启动操作。没有隐式连接替换或自动重连。

`config-get/config-schema/config-check/config-apply` 查询、说明、校验和修改本机 GUI 的 `state/tools`。口令不回显，元数据及运行状态不可写；补丁使用 JSON Merge Patch，配置应用校验通过后批量更新并原子保存一次，保存失败恢复原内存与控件。控制端修改 `state.basic_settings` 时改走专用 `configure` 请求，等待设备端回执；不能与本机其他设置混为一批。设备端的下载/工具配置仍由设备端本机 CLI 修改，不提供远程通用配置 RPC。操作步骤见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md)。

本机日志管理沿用同一CLI IPC,使用`log-get/log-check/log-apply/log-status/log-recover`;日志补丁字段为`log_patch`,仅包含日志对象,恢复字段`path`为调用方显式解析的绝对新文件. 配置复用GUI既有prepare/apply事务;状态直接查询归档拥有者,不以配置开关冒充真实写入状态. 恢复先独占新建并写入未确认批次,只在线程finished后返回唯一`result`,失败保留整批供再次显式另存. 这些是本机文件操作,不新增远程设备RPC,不改变机器RX/JSONL或固件回执. 成功配置提交后仅向人工终端订阅发送有限log-settings事件,包含log_settings及发送快捷/颜色,机器订阅不接收此管理事件.

### BIN 状态机

消息共同字段为 `type=firmware,id`；控制端使用 action，设备端使用 event。

1. `begin(name,size,sha256)`：name 仅文件显示名，不能指定设备端路径；BIN 为 1 字节至 64 MiB，SHA-256 为 64 位小写十六进制。设备端快照自身端口和协议配置，创建随机临时文件并预留设备操作权限，回复 `ready(offset=0)`。
2. `chunk(offset,data)`：严格 Base64，解码后每块 1–32768 字节，顺序偏移必须相等。控制端逐块等待 `chunk_ack(offset=下一偏移)`。乱序、重复块、越界、文件短写均终止上传，尚不接触设备。
3. `commit`：设备端校验全部长度和哈希，停止调试读线程、等待句柄关闭，然后启动共享 FirmwareDownloadWorker。返回 `running`、`progress(current,total,message)`；网络上传进度与设备包进度分别显示。
4. `cancel`：上传阶段清理文件；下载阶段设置取消标志并等待工作线程释放串口。不能把收到取消请求当成设备已经停止。
5. `result(status,message,restored)`：status 为 success/failed/cancelled/unknown；restored 表示清理及调试恢复是否成功。控制端只有 success 且 restored 才按成功继续命令链。

上传空闲 30 秒终止。下载期间双方每秒心跳，15 秒无回应请求取消；控制端提交后收不到结果按未知处理并结束本地任务，此超时处理不会关闭 TCP 连接。设备端收到取消请求、心跳超时或断线时取消持有任务。活动 ID 重复 begin/commit 返回运行状态，已完成 ID 返回缓存终态，绝不重复烧录；设备端进程内缓存最多 1024 个任务，满额拒绝新任务。缓存不跨进程持久化，重启后不能据此判断旧任务结果。

## 下载、占用及恢复规则

设备端上传预留至工作线程退出期间，拒绝冲突发送、参数改变、串口开关和并行下载；只允许状态/端口查询。使用设备端配置，不接受控制端指定的 COM、下载参数或设备端文件路径。控制端 BIN 路径由控制端读取；设备端只读取上传后的临时文件。

共享下载核心检查每次 write 返回数，短写立即停止且不重发。ACK 按固定帧边界累计分段数据，保留后续帧；读取周期最多 50 ms，写超时 1 秒。未启用专用末包 ACK 时，最后一包仍等待普通 ACK。仅 CRC 检查但未配置帧长度的 ACK 会被拒绝；长度和匹配数据同时启用必须一致。

只有通过有效配置的最后一包 ACK 才能报告 success，它代表该协议确认，并不额外证明设备已启动应用。未配置有效完成确认，或发送了现有协议没有完成 ACK 的结束命令，均返回 unknown。设备写入后的取消、超时、短写、断线或异常不能证明最终状态，返回未知；不得据此自动重新烧录。确认设备状态或补全硬件协议后再决定人工操作。

恢复规则：保存实际打开句柄的参数；下载句柄关闭、线程真正结束后，恢复此前已打开的调试连接；此前关闭则保持关闭。不自动恢复设备端连续发送，不发送额外复位/启动指令。恢复失败明确报告；即使固件 ACK 成功也停止后续命令链，避免错误状态继续操作。恢复打开串口本身仍可能触发具体硬件的控制线行为，须上板确认。

## 远程下载操作

1. 设备端电脑运行更新后的串口助手，选择“设备端（连接硬件）”。保留现有监听端口与口令；从设备端当前配置确认实际 COM、波特率、数据位、校验和停止位。本说明没有从 IP 推断这些值。
2. 设备端工具配置中启用固件下载，使用内置下载器（外部 EXE 路径留空）。核对设备已采用的开始命令、包长、CRC、各 ACK 格式及长度、超时和结束设置。远程模式拒绝外部下载 EXE，因为无法保证其取消和完成语义。
3. 操作电脑选择“控制端（远程操作）”，地址填写设备端实际地址（例如占位地址 `192.0.2.10`），TCP 端口及口令填写设备端现有值。连接后确认设备端串口和能力信息。
4. 在控制端电脑点击“固件下载”打开下载窗口,选择本机 BIN 并点击“开始下载”，或发送 `FirmwareDownload:D:\firmware\app.bin`。省略参数时使用操作电脑工具配置的默认文件；设备端默认文件不会代替上传文件。
5. 查看上传、下载进度和终态。需要取消时使用进度窗口“取消”；未知结果停止后续流程，先核查设备状态，不直接重发下载。

## 离线验证及上板待确认项

验证命令及按改动选择检查的原则见 [开发说明](DEVELOPER_NOTES.md#验证与手动构建)。检查覆盖假串口短读短写、分帧/粘包、不同末包 ACK、超时、取消、哈希/边界、断线/心跳、重复 ID、串口冲突、状态恢复、远程结果关联、CLI 子进程及完整回环下载。测试禁止物理串口构造，网络只使用回环接口。

上板前需要用户确认：设备端实际监听端口与口令、COM 与完整串口参数、已验证的 BIN、设备进入下载状态的方法、开始命令、包长和 CRC、开始/普通/末包 ACK 的精确字节与帧长、超时、结束命令及其完成确认含义、串口重开对 DTR/RTS 的影响。回环验证不代表真实设备验收，也不代表跨 Windows 用户的本机桥接支持；本机诊断及结果字段见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md#源码与排障)。
