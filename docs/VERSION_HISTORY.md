## 版本 1.2.6 (2026-10-14)

发布核对时 GitHub 最新正式基线为 `v1.2.2`,并非此前误记的 `V1.2.5`. `master` 已推送至 `0c2b508` (`Release: V1.2.6`),但 `V1.2.3`、`V1.2.4`、`V1.2.5`、`V1.2.6` 的本地轻量标签和对应托管 Release 尚待补发;分支推送不等于标签或 Release 发布. 此后累计变更由下方 1.2.3–1.2.5 章节和本节共同记录,本节保留 1.2.5 之后的最终产品变化. 版本标识仍为 1.2.6 / 2026-10-14,补发保留四个原标签源码提交,旧 EXE 不会自动更新.

发布工具修正:标签前缀接受 `v` 或 `V`,其余版本格式仍严格校验;默认分支提供指定 `release_tag` 的补发入口,校验、打包和说明取目标标签源码. 1.2.3–1.2.5 明确沿用其原发布依赖,历史固件依赖固定到已核对接口的提交,不把当前串口源码挂到旧版本. 发布专项4项检查通过,覆盖两种前缀、非法格式及目标元数据错配;四个原标签的 README/源码版本逐版校验通过,工作流 YAML 及目标检出绑定核对通过. 首次 V1.2.3 CI 三份 EXE 构建通过,但旧 CLI 中文帮助在 runner 的 cp1252 重定向管道输出失败,尚未创建 Release;冒烟改用隐藏独立 Windows 控制台并保留退出码、限时等待和超时进程树清理,不修改历史源码. 本次源码规则修复不表示补发、CI 构建或硬件验收已经完成,实际发布结果以 GitHub Release 和工作流记录为准.

- 新增远程 BIN 上传、SHA-256 完整性校验及设备端下载，复用固件下载器核心。
- 远程角色统一显示为“设备端（连接硬件）”和“控制端（远程操作）”,地址栏统一显示“地址”,使模式、地址、端口控件等宽对齐;同步连接/下载提示、源码说明与操作文档。界面文案与既有 JSON 角色标识分离,配置、CLI schema 和补丁沿用保存值,TCP 协议角色不变。2026-10-22 源码定向验收:GUI CLI 桥接37项通过(55.815s);配置入口、远程能力/下载、固件窗口与断连86项通过(16.731s,测试模块搜索路径包含 checks),覆盖两种角色配置应用、schema 和重启恢复。Windows 原生隐藏窗口截图确认两种角色名称完整显示;未重跑完整套件、未连接硬件或构建 EXE。
- 设备端模式的“地址”下拉框复用串口下拉框的展开信号,每次展开重新获取本机 IPv4 候选,保留当前选择及手动输入;控制端目标地址不被本机 IP 覆盖。2026-10-22 隔离 Qt 冒烟检查通过,覆盖重复展开刷新、旧候选移除、输入保留及刷新不触发值变化信号;未连接真实设备或重新打包。
- 统一下载期间的串口独占，处理取消、断线和调试状态恢复；结果未知时不自动重烧。固件按钮先打开完整下载 UI,浏览/拖放只选文件,点击开始后才提交共用任务;本机编辑本次串口/协议参数,远程沿用设备端配置,窗口展示进度和日志,取消/关闭等待终态和资源恢复。精确预选端口,避免 COM7 匹配到 COM70;本次参数不覆盖持久化默认值。
- 远程设备操作增加能力协商、请求关联和结果回执，命令链等待实际操作结果；普通透传不保存已完成请求历史，移除连接累计 4096 次限制，ID 仅关联回执、不保证跨帧幂等，结果未知不自动重发，固件任务去重保持不变；修复停止连接与线程退出并发清理 socket 时的竞态，避免空引用异常逃出 `QThread.run` 导致 Python 进程原生终止，并增加真实线程交错的隔离回归。
- 新增 CLI 到运行中 GUI 的本机桥接，窗口同步显示操作、进度及最终结果。
- 修复桥接控制台失联后仍等待输入及重复错误的问题,任务连接异常也会非零退出;远程意外失联由 GUI 与在线 CLI 共享同源错误,中止后续命令,未确认操作保留 unknown,主动停止及正常一次性请求不误报.
- 增加常驻控制台 `--console`，本机和 GUI 桥接共用命令执行器；支持模块、取消、日志和固件下载，退出 CLI 不关闭 GUI。
- 新增显式 --via-gui --console --machine 机器常驻接口,UTF-8 JSONL 保留调用方 ID、原始 RX 分片、实际 task 与采集窗口;首次真实目标/连接握手不隐式 Open,成功响应窗口显式关闭后再提交下一条. 状态/终态有序,主动漂移/断连停止,下载独占及恢复单独核对,EOF 不伪造终态或自动取消. 机器stdout写入失败退出2,stdin仍开也停止;不递归写坏stdout,stderr可用时仅报告一次,不取消或重放已受理GUI任务. 正式单次和人工控制台保持原契约,机器 RX 窗口不声明无 wire ID 的设备因果.

- 新增运行中切换工作 JSON,GUI 与 CLI 共用加载/切路径事务;切换不写旧/新文件,后续修改只保存到新文件,保留当前串口/远程连接,任务中拒绝. 桥接端点仍由启动配置定位,查询与结果返回实际工作路径和桥接路径.
- 扩大完整 `config-get` JSONL 回执上限至 4 MiB，并由结果公布字节上限；仅当前请求匹配 ID、配置对象和容量声明的成功终态可使用对应待发送额度，普通请求/回执与累计待发送上限保持原值；超限仍返回关联失败且不截断。
- CLI 增加直接导入/导出 CSV/TXT 命令模板；独立模式调用共享纯函数，共存模式与 GUI 按钮调用同一异步接口，由 GUI 实际读写并显示进度、支持取消/回滚，大模板不经 IPC 整表透传。导入复用已有同行控件,减少重复控件创建;新增空行结构一次分配,后续分块填控件,避免逐行插入结构,保留分块响应、原子保存和回滚;旧待校验结果继续计数但不再给新行染色,替换模式快捷键在事务忙碌期间不改变设置。本机及 GUI 桥接的一次性命令/控制台支持流式追加原始 RX，保留原 Log 会话日志语义；文件结果及 RX 保存状态统一文案，两端各显示一次，失败不自动重发设备操作。
- 系统信息采用事件原始时刻,GUI按日志配置中的独立时间戳选项决定是否保留时刻,重绘不重新计时;桥接JSON独立传播timestamp,独立CLI的Log及原始RX字节不变。
- 修复 GUI 模板导入/导出未更新最近目录的问题,两者共用最近选择目录并持久化,取消及 CLI 显式路径不污染偏好;同目录跳过重复保存,偏好保存失败显示错误并恢复原值。
- 修复远程替换发送把入队当写入完成而提前耗尽响应校验时间的问题;复用成功写入回执后登记校验,不增加超时、不回放旧 RX、不自动重发,保留本地校验时机并防止复位/行变化后的迟到关联。无已保存全局规则时弹窗预填默认草稿,取消不写入,已有自定义和显式清除仍保留;默认响应表达式收紧为匹配通道、回显地址、读回地址和值,避免仅值相同就误通过,等待读回行结束后判断。已保存规则不自动改写,主动恢复默认才更新模板。

#### CSV 导入导出问题

**问题1：双引号累积**
- **现象**: 导出导入循环后，注释字段中的双引号不断累积
- **根本原因**:
  - 导出时：csv.writer 自动添加引号，同时手动转义导致双重转义
  - 导入时：使用手动字符串分割 `split(',')` 无法正确处理 CSV 标准引号
- **解决方案**:
  - 导出：显式指定 `quoting=csv.QUOTE_MINIMAL`，让 Python csv 模块自动处理引号
  - 导入：使用 `csv.reader()` 替代手动分割，自动处理 CSV 标准转义
- **当时参考文档**: `BUG_FIX_CSV_QUOTE_ACCUMULATION.md`（历史文件，当前仓库未保留）

**问题2：BOM 字符导致第一行无法识别**
- **现象**: 部分 CSV 文件（如 RxCH1+RxCH2+TxCH1+TxCH2.csv）第一行无法识别
- **根本原因**: 文件包含 UTF-8 BOM 字符 (0xEF 0xBB 0xBF)，导致第一列被解析为 "﻿False" 而非 "False"
- **解决方案**: 将 `encoding='utf-8'` 改为 `encoding='utf-8-sig'`，自动移除 BOM
- **位置**: [main_window.py:1353](../main_window.py#L1353)

**问题3：多列注释解析**

- **好处**: 用户可以在注释中使用任意数量的逗号，不会被当作列分隔符
- **示例**:

### 新增功能

#### StopContinuous 特殊指令

**功能**: 控制连续发送流程，可选择提前结束本轮或完全停止

**格式**: `StopContinuous:参数`

**参数说明**:
- `0` 或 空 - 提前结束本轮，继续循环（默认）
  - 停止执行当前轮的后续命令
  - 保持循环发送勾选状态
  - 等待循环间隔后，自动开始下一轮
  - 适用场景：提前结束本轮测试，立即进入下一轮循环

- `1` - 完全停止连续发送和循环发送
  - 停止执行当前轮的后续命令
  - 取消循环发送勾选
  - 完全停止，不再继续
  - 适用场景：完全停止所有自动发送功能

**系统消息**:
- 参数为 0: `"StopContinuous: 提前结束本轮发送，等待下一轮循环"`
- 参数为 1: `"StopContinuous: 已停止连续发送和循环发送"`

**应用场景**:
```
命令序列示例（勾选了"循环发送"）：
第一轮:
1. [✓] AT+TEST1              ← 执行
2. [✓] AT+TEST2              ← 执行
3. [✓] StopContinuous:0      ← 执行，提前结束本轮
4. [✓] AT+TEST3              ← 不执行（已跳过）

等待循环间隔...

第二轮:
1. [✓] AT+TEST1              ← 执行
2. [✓] AT+TEST2              ← 执行
3. [✓] StopContinuous:0      ← 执行，提前结束本轮
4. [✓] AT+TEST3              ← 不执行（已跳过）

...（继续循环）
```
