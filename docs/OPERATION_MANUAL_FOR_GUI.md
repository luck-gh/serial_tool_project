# GHowe 串口调试助手 GUI 操作手册

适用版本：V1.2.6 待发布源码对应的 Windows EXE。旧 EXE 不会随源码自动更新，新增能力需用户手动构建后使用。

本文档面向直接使用可执行文件的用户，说明图形界面的日常操作、快捷键、查找与替换发送，以及发送编辑区支持的特殊命令。点击主窗口左下角 `?` 并选择“GUI 操作手册”，或按 `F1`，即可随时查看本文档。

## 1. 快速开始

1. 双击通用版或 GUI 专用版 EXE 打开程序。
2. 在左侧“基础设置”中选择串口和通信参数。
3. 点击“打开串口”，或按 `Ctrl+O`。
4. 在右侧发送编辑区新增或编辑命令。
5. 点击命令行的发送按钮发送单条命令。
6. 需要批量发送时，勾选命令行并使用“连续发送”。

正式发布的 EXE 文件名可能包含版本后缀，不影响图形界面操作。主界面配置、命令或布局变化后自动防抖保存；底部“配置”窗口内的参数点击“确定”才生效并写入JSON，取消不改变配置。关闭窗口时还会执行最终保存。

通用版和 GUI 专用版均可用 `--config "D:\配置目录\串口 配置.json"` 选择配置，也支持 `--config=路径`。相对路径按启动进程的工作目录解析；省略时仍按当前工作目录和可执行文件名生成默认配置名，忽略 `_GUI`/`_CLI` 后缀。CLI 桥接须指定同一启动配置路径,运行期切换工作 JSON 后仍沿用原桥接定位路径，详见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md)。

## 2. 界面区域

- **基础设置**：串口、波特率、数据位、校验位和停止位。
- **远程控制**：在设备端和控制端之间共享串口数据与控制。
- **接收设置**：控制输出来源、保存接收数据和清空显示。
- **发送设置**：结尾标识符、发送显示颜色、替换发送和发送间隔。
- **发送编辑区**：编辑多条命令、备注、模块和独立替换规则。
- **模板相关**：导入或导出命令模板。
- **工具相关**：打开已启用的转换器和辅助工具。
- **帮助与配置**：`?` 打开 GUI/CLI 操作手册，“配置”用于管理程序和外部工具设置。

`Ctrl+F` 会根据当前焦点选择查找目标：焦点在接收区时查找接收文本，焦点在发送编辑区时查找发送命令。

## 4. 串口操作

### 4.1 打开与关闭

- 点击“打开串口”或按 `Ctrl+O` 建立连接。
- 连接成功后按钮显示“关闭串口”。
- 再次点击或按 `Ctrl+O` 关闭连接。
- 如果正在连续发送，关闭串口会先停止连续发送。

### 4.2 结尾标识符

“发送设置”中的结尾标识符会追加到普通字符串命令末尾。

| 选项 | 实际追加内容 |
| --- | --- |
| `None` | 不追加 |
| `\r\n` | 回车加换行 |
| `\r` | 回车 |
| `\n` | 换行 |

### 4.3 显示与保存接收区数据

“接收设置”中的“输出来源”和“系统级别”只筛选显示,不决定日志收录或文件保存。“显示时间戳”位于系统级别下面,只显示已经保留的时间。其下方为“保存完整日志”开关及右侧的“日志目录…”快捷按钮,再下方为保存数据和清空数据按钮。固件下载等信息保留 `FirmwareDownload:` 前缀。关闭“系统”来源时所有级别隐藏,重新打开后按当前显示级别筛选。

底部“配置”窗口从上到下为“版本信息”“工作 JSON”“配置”三块。版本信息常驻显示,左列为工具版本和工具更新时间,右列为配置文件版本和配置最后更新时间;下方配置区分为“日志配置”和“工具配置”页签。日志规则在“日志配置”页中编辑,点击“确定”后与工具配置一起保存并生效;取消不改变收录、历史上限或文件路径,保存失败保留弹窗并回滚运行态。数据先按日志配置收录,接收区再筛选;未收录的信息即使打开显示也不会出现。日志配置变更不追溯删除已有历史,也不补回此前舍弃的信息。

| 日志配置 | 行为 |
| --- | --- |
| 日志上限 | 默认4 MB,范围1–1024 MB,1 MB = 1,000,000字节。按临时记录及其正文、时间戳、元数据的内存预算计算,超限淘汰最早记录至约75%;调低上限也会淘汰历史。界面排版和后台文件批次另有开销,不是整个进程的硬性内存上限,也不限制文件大小。 |
| 保留全量信息 | 默认开启,收录全部来源和系统级别。关闭后按“保存到日志中”的来源及级别收录。不会强制开启时间戳。 |
| 保存到日志中 | 分别选择发送、接收、系统、错误及系统级别。全量保留开启时显示全部选中并暂时禁用,关闭后恢复原有自定义选择。 |
| 保留时间戳 | 默认开启,独立决定新记录是否保留事件时间。与全量保留、显示时间戳都相互独立。 |


主界面“接收设置 → 保存完整日志”默认关闭,切换即时生效并自动保存开关状态;开启期间分块记录符合日志规则的新信息,不回灌此前未开启文件保存期间的信息。启停只通过勾选状态表示,不再常驻状态文字;关闭后尚有批次在写时,下方临时显示“正在保存尾部”。文件错误和“另存未确认日志”入口也留在主界面,不藏在配置窗口中。

“发送设置 → 显示发送字符串”是临时快捷入口,颜色选择继续保留:

- 开启时,接收设置和日志配置中的“发送”都呈现选中、暂时不可修改,悬停提示由发送设置开启;两处原有选择仍保留。
- 关闭时,恢复两处各自的基础选择。日志全量保留若仍开启,日志“发送”继续由全量保留启用。
- 关闭快捷入口不代表停止记录发送信息。发送是否收录由日志配置决定,是否显示由接收设置决定。需要分别编辑时先关闭快捷入口,日志来源还需关闭全量保留。
- 配置保存记录基础选择和快捷入口状态,重启及切换工作配置后仍能正确恢复;颜色不受联动禁用影响。

关闭日志“保留时间戳”期间的记录没有时刻,之后打开显示也不会补造。已保留的时间可以在接收区隐藏或重新显示;文件和手动导出使用实际保留的时间戳,不受当前显示开关影响。CLI协议事件时间独立于GUI日志设置。

接收时间戳在成功发送后的首段 RX 显示,同一接收内容的后续分片或换行不重复添加. 设备端接受远程写入也使用这一边界,不依赖“显示发送字符串”是否勾选;失败不建立新边界,每个实际成功写入的新请求帧均重置边界. 两端各按本机收到 RX 的时刻显示,不互传或替换另一端的时钟.

接收区采用流显示，每约 20ms 分批排版，历史筛选也分批重绘。系统和错误信息在残缺接收行期间仍有约 20ms 固定宽限；换行、发送或关闭时提前释放，连续接收不会重启宽限。超长无换行内容在显示层分段换行，保留记录和文件不插入这些显示换行。原始 RX、CLI 和响应匹配不经过显示队列；展示不判定协议包边界。接收区向下跟随新内容，手动向上滚动时暂停跟随；达到历史上限后删除最早内容，可回看的范围随之移动。

文件目录可从主界面“日志目录…”快捷选择,也可在“配置 → 日志配置 → 日志目录”中编辑,共用 JSON 中的 `state.log_settings.log_directory`。快捷选择后立即保存,配置弹窗中的选择在点击“确定”后保存;取消选择或保存失败保留原值。缺省为当前工作配置目录下的 `logs`,每次程序运行首次开启保存时生成唯一 `serial-*.log` UTF-8 文件;主界面目录按钮的悬停提示显示配置目录及已有日志文件路径。同次运行关闭后再开启,目录不变时继续追加同一文件,中间关闭期间的信息不回灌。保存开启、尾部未写完或尚有失败批次时,两个目录按钮均禁用;先关闭保存并等待写完,失败时先另存未确认日志,再选择目录。修改目录后开启会创建新文件。

待写批次的内存预算达到日志上限约 80% 时，由后台线程写入一整批；完整写入并刷新成功后才推进保存位置。正常关闭保存、清空数据及退出会补写不足一批的尾部。清空或历史淘汰不会删除已有文件；异常退出或断电可能丢失未写入批次。磁盘写入失败或持续跟不上接收速度时明确停存并显示错误，未确认批次暂留，使用“另存未确认日志…”保存到新文件；原文件尾部可能部分写入，不会自动重试。另存成功后可重新勾选保存，失败期间未归档的新信息不自动补入。

CLI可用`--via-gui --log-action status`读取实际文件路径、在写状态、已提交序号及未确认数量,用`--log-action recover --log-recover 新路径`调用同一个另存入口,实际写完后才返回结果. 日志配置事务也会同步到已连接的人工终端;原始RX和机器JSONL保持独立,终端会话显示时间戳偏好不被覆盖. 参数及示例见[CLI手册](OPERATION_MANUAL_FOR_CLI.md#命令与语义).

“保存数据”用于手动导出当前仍保留的临时历史，可独立选择来源和系统级别。它能导出保留但当前隐藏的信息，不能恢复产生时舍弃或超限淘汰的内容，也不重新读取已归档文件。显示和文件保存开关自动保存;日志规则和上限在配置窗口确认后保存,目录按所用入口确认后保存。

“清空数据”清除接收区和临时历史。开启文件保存时先请求补写已收录的尾部，现有文件继续保留；未开启时需要保留的内容应先手动保存。

## 5. 查找

### 5.1 接收区查找

1. 点击接收显示区。
2. 按 `Ctrl+F`。
3. 输入查找内容。
4. 按 `Enter` 查找下一个，按 `Shift+Enter` 查找上一个。

所有匹配内容都会以浅黄色背景高亮，当前匹配项使用稍深的黄色。查找不会把输入焦点强制切换到接收内容。

### 5.2 发送编辑区查找

1. 点击任意发送命令编辑区。
2. 按 `Ctrl+F`。
3. 点击“范围”，在弹窗中选择模块范围和搜索区域。
4. 搜索区域可选择“字符串”“备注”或“一起搜索”。
5. 模块范围支持多选；模块较多时可在列表中滚动浏览，也可直接选择“全部模块”。
6. 确认范围后，输入内容并连续按 `Enter` 浏览匹配项。


### 5.3 查找选项

- **区分大小写**：大小写必须完全相同。
- **正则表达式**：按正则语法解释查找内容。
- **全字符匹配**：只匹配完整单词或完整字符边界。
- **范围**：发送区可在弹窗中多选模块，并选择搜索字符串、备注或两者；模块列表支持滚动。

正则表达式无效时，查找栏会提示错误，不会修改命令内容。

## 6. 替换发送

替换发送只在数据发出的瞬间生成临时发送内容，发送编辑区中的原始字符串保持不变。

### 6.1 全局替换规则

1. 在“发送设置”中点击“全局规则...”。
2. 输入查找内容、替换内容；需要校验设备响应时再填写响应表达式。
3. 根据需要设置区分大小写、正则表达式和全字符匹配；需要校验时勾选“开启响应匹配”。
4. 勾选“替换发送”，或按 `Ctrl+T`。

默认全局规则会把 `write <通道> 0x<地址> 0x<值>` 转为 `read <通道> 0x<地址> 1`。没有已保存规则时,打开全局规则弹窗会自动预填默认草稿;取消不改变运行态和文件,确定后保存。已有规则按原值加载,不会被默认模板覆盖。点击“默认规则”可主动重新填入当前默认查找、替换和响应表达式,同时把当时的连续发送间隔复制为本规则的独立超时时间;点击后弹窗不会自动关闭。“开启响应匹配”默认关闭,需要使用时手动勾选。

默认响应表达式要求读命令回显的通道、地址及下一行读回的地址和值对应原命令,等待读回行结束再判断,值允许前导零和可选的 `0x` 前缀。例如 `read 0 0x40108048 1` 后紧接 `40108048 = 0803C0C8` 并换行;通道/地址不同不会仅因值相同而通过。远程模式收到设备端串口写入成功回执后才开始响应超时,此前 RX 不参与本次校验;正确分片响应仍可拼接匹配。已保存旧表达式的配置需主动点击“默认规则”并确定后更新。

点击“清除规则”只会清空弹窗内容，不会立即关闭；继续点击 OK 才会删除该规则，点击 Cancel 则保留原规则。清空后重新填写内容并点击 OK 会保存新规则。

### 6.2 命令行独立规则

1. 在发送编辑区选中一行或多行。
2. 右键打开菜单。
3. 选择“设置选中行规则”。
4. 输入所选命令行使用的替换规则。

拥有独立规则的命令行会显示规则标记。独立规则优先于全局规则。选择“清除选中行规则”可以移除所选行的独立规则。

### 6.3 是否可替换

程序使用与查找功能相同的匹配逻辑判断命令是否可替换：

- 能查找到匹配内容时，发送按钮进入可替换提示状态。
- 找不到匹配内容时，发送按钮保持普通状态。
- 连续发送中，能匹配的命令发送替换后内容；不能匹配的命令直接发送原始内容。

### 6.4 正则分组替换

开启正则表达式后，可以在查找内容中使用圆括号定义捕获组，并在替换内容中引用。

| 替换写法 | 含义 |
| --- | --- |
| `$1` | 第 1 个捕获组 |
| `${1}` | 第 1 个捕获组的明确写法 |
| `$2` | 第 2 个捕获组 |
| `$&` | 本次匹配到的完整文本 |
| `$$` | 字面量 `$` |

示例：

- 查找：`AT\+(\w+)=(\d+)`
- 替换：`CMD:$1,VALUE:$2`
- 原始命令：`AT+MODE=3`
- 实际发送：`CMD:MODE,VALUE:3`

### 6.5 响应表达式校验

响应表达式也是正则查找表达式。普通正则只负责在发送后的接收数据中查找响应；`$1`、`$2`、`${name}` 等引用上方“查找”表达式的捕获值，同时要求响应中的对应位置与原始值一致。

勾选“开启响应匹配”后，响应表达式输入框和右侧“设置...”按钮才可用。“设置...”弹窗用于配置独立超时、失败后继续或停止、循环策略及是否显示匹配系统错误；循环策略默认使用“失败后保持红色”，“显示匹配系统错误”默认关闭。

例如：

- 默认查找：`^write\s+(\d+)\s+(?:0x)?([0-9A-Fa-f]+)\s+(?:0x)?0*([0-9A-Fa-f]+)\s*$`
- 替换为：`read $1 0x$2 1`
- 默认响应表达式：`read [01] 0x\w* 1\W*\w*\s*=\s*0*$3\W`

默认响应表达式只校验写入值，并允许设备返回值带有额外前导零。如果需要同时校验通道、地址和值，可以使用：

`read $1 0x$2 1\r?\n$2\s*=\s*0*$3\W`

默认表达式中的 `[01]`、`\w*` 等普通正则只负责查找，只有 `$3` 与原始写入值比较。支持 `$1`、`${1}`、`${name}` 和 `$$`；引用不存在的捕获组时无法保存规则。

串口接收数据会按连续数据流处理：一条响应可以跨多个串口包，一个串口包也可以完成多条校验。同一段响应只会分配给一个待校验任务；存在冲突时优先分配给最早发送的任务。

本地发送后登记校验;远程替换发送则在设备端确认串口写入成功后登记并开始原有响应超时,排队及等待写入回执不消耗响应期限. 设备端当前实现先发送写入回执,再转发该次写入产生的 RX;回执前已有的旧/异步 RX 不参与新校验. 写入回执不代表设备命令已完成,仍须响应匹配;写入失败或结果未知不登记校验且不自动重发. 等待回执期间复位统计不重新登记旧校验,修改或删除原行也不会让迟到结果给新命令染色.

- 校验通过：对应发送字符串单元格显示淡绿色。
- 校验失败或超时：对应单元格显示淡红色。开启“显示匹配系统错误”后，错误信息会同时显示替换后实际发送的字符串；如果收到完整响应但校验值不同，还会显示具体值差异，只有无法找到完整响应结构时才显示超时详情。
- 直接点击发送和未开启循环的连续发送：始终显示最近一次校验结果，后续通过可以覆盖红色。
- 循环策略“显示最近一次结果”：循环发送时，后续通过可以覆盖红色。
- 循环策略“失败后保持红色”：循环发送时，保持红色直到复位、修改命令或修改规则。
- 失败后可选择继续发送或停止连续发送。
- 统计栏中的“校验通过: n/x”只统计已经完成的校验。
- 点击“复位”会同时清除校验统计、等待中的校验和单元格状态颜色。

### 6.6 按钮颜色

- 替换发送模式下，可替换的单条发送按钮使用紫色背景和白色文字。
- “全局规则...”按钮使用紫色背景和白色文字。
- 替换模式下的连续发送按钮使用紫色背景和白色文字。
- 普通连续发送运行状态使用橙色提示。

## 7. 连续发送与循环发送

### 7.1 连续发送

1. 勾选需要执行的命令行。
2. 在“连续发送模块”中选择“全部”或指定模块。
3. 设置“连续发送间隔(ms)”。
4. 点击“连续发送”，或按 `Ctrl+R`。
5. 再次点击或按 `Ctrl+R` 停止。

连续发送会在一次发送单元内完成查找、替换判断和实际发送，不会另外修改命令内容。

### 7.2 循环发送

勾选“循环发送(ms)”后，一轮连续发送结束会等待设定间隔，再开始下一轮。

## 8. 命令行与模板

命令行优先显示实际发送文本,右侧注释仅使用剩余空间且最多占输入框约 40%,过长省略,没有空间时隐藏. 双击该行左侧选择框可查看/编辑完整注释;显示省略不会改变保存的注释或发送命令.

### 8.1 多行选择

发送编辑区支持选择多行。右键菜单中的规则操作会显示为“设置选中行规则”和“清除选中行规则”，并应用到全部所选行。

### 8.2 模块

模块用于组织一组命令，便于跳转和连续发送。模块由 `mode` 和 `modeend` 特殊命令定义。

### 8.3 模板导入与导出

- “导入模板”解析成功后替换命令、备注和启用状态；模块来自命令标记，旧行替换规则清空，不修改串口或远程参数。
- “导出模板”原子保存当前命令表。CSV/TXT 使用相同的三列 CSV 格式，不是完整配置文件，也不是 Excel 工作簿。
- 导入与导出共用最近一次选择文件的目录,重启后保留;取消选择不更新,选定后即记录目录,即使随后模板解析或读写失败. 同目录不重复保存此偏好,导出仍只预选目录、不填默认文件名;CLI 显式文件路径不改变 GUI 目录偏好. 偏好保存失败时显示错误并保留原目录.

GUI 按钮与共享 CLI 使用同一异步导入/导出接口，窗口显示进度并可取消；提交前取消或保存失败恢复原表。最终原子保存开始后等待保存结果。系统完成/失败提示与 CLI 相同。

CLI 可直接导入/导出同一模板；也可流式追加运行期间的原始 RX，与 GUI 按来源导出当前历史的“保存数据”范围不同。入口及具体文件语义见 [CLI 文件操作](OPERATION_MANUAL_FOR_CLI.md#模板与接收文件)。
- 导入前建议先导出现有配置作为备份。

### 8.4 运行中切换工作 JSON

在“配置”弹窗点击“切换工作 JSON...”选择已有文件,加载命令、注释、替换规则及其它工作设置,后续修改保存到该文件. 切换本身不保存或覆盖旧文件,也不写选定文件;放弃旧文件未保存的编辑. 当前串口和远程连接及其参数保持不变,文件中的 basic_settings/remote_settings 不应用到当前连接,后续保存以保留的实际工作设置为准. 任务、响应校验、机器采集窗口或模态编辑尚未结束时拒绝切换. 取消、读取或校验失败不切换;同一文件不重载. 文件须存在且未标记只读;实际保存仍可能因权限或存储状态失败并通过原保存错误渠道报告.

CLI 的 `--config` 仍指向启动时桥接定位文件,切换后不更换端点或新建服务. `status`、`config-get` 和切换结果的 `working_config_file` 是实际后续保存路径,`bridge_config_file` 是 CLI 继续使用的定位路径. 重启仍由启动参数选择 JSON,不会修改其它文件来记住本次切换.

## 9. 特殊命令

特殊命令写在发送编辑区中，由程序解释，不会全部作为普通字符串直接发送。

| 命令 | 示例 | 作用 |
| --- | --- | --- |
| `mode` | `mode:初始化` | 定义模块开始位置 |
| `modeend` | `modeend:0` | 定义模块结束位置 |
| `delay` | `delay:500` | 延时指定毫秒数 |
| `SendHex` | `SendHex:AA 55 01` | 按十六进制字节发送 |
| `BaudRate` | `BaudRate:115200` | 修改当前波特率 |
| `ComPort` | `ComPort:COM3` | 切换串口 |
| `SetEndlog` | `SetEndlog:\r\n` | 修改结尾标识符 |
| `SendMode` | `SendMode:初始化` | 执行指定模块 |
| `StopContinuous` | `StopContinuous:0` | 控制连续发送停止方式 |
| `FirmwareDownload` | `FirmwareDownload:D:\firmware\app.bin` | 调用固件下载工具下载文件 |

### 9.1 模块结构

- `mode:name`：定义名为 `name` 的模块起点。
- `modeend:0`：定义当前模块结束位置。

### 9.2 延时与发送

- `delay:milliseconds`：暂停后续命令指定毫秒数。
- `SendHex:hex-bytes`：按十六进制发送字节，例如 `SendHex:AA 55 0D 0A`。

### 9.3 串口配置命令

- `BaudRate:value`：修改当前波特率。
- `ComPort:port`：更新端口选择；已经打开的句柄不切换，关闭重开后生效。控制端更新设备端选择。
- `SetEndlog:value`：设置后续普通字符串命令的结尾标识符。

### 9.4 模块控制命令

- `SendMode:name`：触发指定模块的连续发送。
- `StopContinuous:0`：结束当前轮次，但保留循环发送状态。
- `StopContinuous:1`：停止连续发送，并关闭循环发送。

### 9.5 固件下载命令

点击“工具相关”中的固件下载按钮,先打开完整下载窗口,不会立即弹出 BIN 选择框或启动下载。在窗口内浏览或拖放文件、查看参数后,点击“开始下载”才执行。本机模式可修改本次串口和下载设置,不会覆盖主窗口或工具的默认配置;打开窗口本身不关闭串口。远程模式在窗口选择本机 BIN,串口和协议参数仍使用设备端配置,不显示本机参数编辑入口。进度和日志显示在下载窗口中,停止、Esc 或关闭操作会请求取消正在执行的任务;任务结束并完成资源恢复后才能关闭窗口。

- `FirmwareDownload:`：使用“固件下载工具”配置中的默认固件文件。
- `FirmwareDownload:path`：使用指令参数指定的固件文件；路径包含空格时可使用双引号。
- 固件文件优先级为“指令参数 → 固件下载工具默认文件”。未指定有效文件时，下载不会启动。
- 下载的包大小、开始命令、CRC、ACK 和超时设置全部沿用固件下载工具配置。
- 下载开始前会释放串口助手占用的本地串口；下载完成后会恢复此前已打开的串口。下载失败或用户停止连续发送时，本轮连续发送停止。
- 该指令仅在“配置”中启用固件下载工具且工具可用时显示。如果右键菜单中没有该指令，请检查工具是否启用、默认固件和工具路径是否有效。
- 控制端会读取操作电脑的 BIN 并上传，由设备端使用自己的串口和下载协议配置执行；下载窗口点击开始后与指令共用检查及任务入口。远程设备端须使用内置下载器。详细配置及“结果未知”的处理见 [远程下载说明](REMOTE_PROTOCOL.md)。
- CLI 一次性下载须用 `--via-gui` 交给窗口；常驻控制台的独立/桥接后端均支持 `FirmwareDownload`。窗口、远程及未知结果约束见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md#命令与语义)。

### 9.6 与 CLI 协作

GUI 运行时，同一 Windows 用户的 CLI 可通过 `--via-gui --config` 操作它持有的串口，窗口同步显示操作与结果；CLI 退出不关闭 GUI。桥接定位路径必须与 GUI 启动时的配置绝对路径一致,运行期切换工作 JSON 后仍使用该原路径，目前不支持跨用户桥接。Agent 可使用一次性命令并检查最终回执,也可用显式 `--console --machine` 复用同一进程及 RX 窗口;后者要求目标已连接空闲且调用方验证完整响应,不自动 Open. 精确契约见 [CLI 手册](OPERATION_MANUAL_FOR_CLI.md#机器常驻接口)。

## 10. 远程控制

远程控制用于让一台电脑操作另一台电脑连接的串口。连接串口设备的电脑作为“设备端”，发起操作的电脑作为“控制端”。两端应使用相同端口和密码，并确保网络与防火墙允许连接。

### 10.1 设备端

1. 在“远程控制”中选择“设备端（连接硬件）”,即连接串口硬件并提供 TCP 监听的电脑。
2. 设置监听端口和连接密码。
3. 根据需要先打开本机串口；也可以在控制端连接后再请求打开。
4. 点击“启用远程控制”，等待状态显示“监听中”或“已连接”。
5. 将设备端电脑的可访问地址、端口和密码提供给控制端用户。

两种角色的地址栏均标为“地址”,与“模式”“端口”的控件保持等宽对齐。设备端模式下,每次展开地址下拉框都会重新获取本机 IPv4 地址,与串口下拉框展开时刷新列表的操作一致。刷新保留当前选择或手动输入,只更新候选列表;控制端模式保留目标地址,不替换为本机 IP。

### 10.2 控制端

1. 先关闭本机直接打开的串口。
2. 在“远程控制”中选择“控制端（远程操作）”,通过 TCP/IP 操作设备端的串口硬件。
3. 输入设备端地址、相同端口和密码。
4. 点击“启用远程控制”，等待状态显示“已连接”。
5. 在“基础设置”中选择设备端提供的串口参数，再点击“打开串口”。

远程控制启用后，关注“远程”状态文字和接收区中的系统、错误信息。连接异常时，先确认两端地址、端口、密码和防火墙设置，再重新启用远程控制。

远程对端意外断开时,本窗口显示错误;在线 CLI 订阅者和有在途请求的一次性 CLI 共享同一错误文案及时间.
主动本地停止连接不报告意外断连,但在途操作仍须终结;已发出且未收到确认的操作保留结果未知,不自动重发或重新下载.
设备端监听端在客户端丢失后仍可保持监听.正常 CLI 请求结束或 Quit 不作为窗口故障;
GUI 本身关闭或崩溃时,CLI 报错退出,已退出的 GUI 无法显示后续错误.

## 11. 常见问题

### 串口无法打开

- 检查串口是否被其他软件占用。
- 刷新串口列表并重新选择。
- 检查波特率、数据位、校验位和停止位。

### 替换按钮没有变色

- 确认已开启“替换发送”。
- 确认规则能在当前命令中查找到内容。
- 检查大小写、正则表达式和全字符匹配选项。
- 如果命令有独立规则，优先检查独立规则。

### 连续发送中途停止

- 检查串口是否断开或被其他软件占用。
- 检查响应校验规则是否设置为“失败后停止”。
- 检查是否执行了 `StopContinuous:1`。
- 如果流程包含 `FirmwareDownload`，检查固件文件、下载参数和设备响应。

### “?”中的手册与当前功能不一致

操作手册与 EXE 版本对应。请先确认正在使用的程序版本，并使用同一版本附带的帮助内容；升级 EXE 后重新打开“?”窗口即可查看该版本手册。
